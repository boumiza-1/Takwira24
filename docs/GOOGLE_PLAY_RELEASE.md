# Takwira24 — Google Play release & updates (Capacitor)

The Android application id is **`com.princo.takwira24`**. Keep it stable after the first Play Store upload. The Android project is generated on every build, so never commit an Android keystore or a service account private key.

## One-time prerequisites

1. Create Takwira24 in Google Play Console with app id `com.princo.takwira24` and complete its store listing / required declarations. Follow the Play Console testing rules for your account.
2. Create a permanent upload key on your own secure computer, e.g. `keytool -genkeypair -v -keystore takwira24-upload.jks -alias takwira24-upload -keyalg RSA -keysize 3072 -validity 10000`.
3. **Back up this keystore and its passwords offline. Do not send them by chat, email or put them in GitHub source code.** Google Play App Signing manages the Play app signing key; your upload key signs submitted AABs.
4. Set repository secrets in GitHub → Settings → Secrets and variables → Actions:
   - `T24_UPLOAD_KEYSTORE_BASE64` — base64 contents of `takwira24-upload.jks` (not the path). On Linux: `base64 -w 0 takwira24-upload.jks`. On Windows PowerShell: `[Convert]::ToBase64String([IO.File]::ReadAllBytes('takwira24-upload.jks'))`.
   - `T24_UPLOAD_STORE_PASSWORD` — keystore password.
   - `T24_UPLOAD_KEY_ALIAS` — alias, e.g. `takwira24-upload`.
   - `T24_UPLOAD_KEY_PASSWORD` — alias password (can be same as store password).
5. For internal-test API uploads only: configure a Google Cloud service account with Google Play Developer API access and least-privilege Play Console release permission. Store its full JSON in `GOOGLE_PLAY_SERVICE_ACCOUNT_JSON`. The app must be set up / first AAB upload completed in Play Console before relying on API updates.
6. GitHub → Settings → Environments: create `google-play-upload`, restrict it to the `main` branch, and add **Required reviewers** to enforce approval before the internal-test upload. GitHub availability of reviewer protections depends on repository visibility and plan. This workflow **never submits to production**. For production use Google Play Console to review and promote an approved tested release.

## Building a signed AAB

From GitHub → Actions → **Takwira24 — Signed Google Play AAB** → Run workflow:
- Enter a **new** `version_code` greater than any version previously uploaded to Google Play (e.g. `1` for the first release).
- Enter a user-facing `version_name` such as `1.0.0`.
- Set `release_action=build_only` to produce a downloadable `app-release.aab` under the workflow's **Artifacts**. Upload that AAB in Play Console manually for the first release or an approved update.
- Set `release_action=internal_testing` to build and upload to the **internal** test track only after any configured GitHub Environment approval. This requires Google Play API credentials.
- For publishing to the public, go to Play Console to review and publish/promote the update yourself.

## Subsequent updates

1. Edit Takwira24 React code on GitHub and test the GitHub Pages app.
2. Run the signed Google Play AAB workflow with a larger `version_code`.
3. Verify it in internal testing; publish to Production only after your approval in Play Console.
4. The existing Supabase database preserves user profiles and matches. Check any database schema changes for backward compatibility with installed clients.

### Important

- Debug APKs generated by the separate `Build Takwira24 Android APK` workflow cannot be uploaded to Google Play.
- Never replace your keystore or change the app id on future updates.
- Native Capacitor bundles include the web UI. A change on GitHub Pages alone **does not update the installed Play Store application**: you must build and publish an updated AAB.
- The workflow needs its signing secrets to compile a **signed** AAB; until you add them, signed releases cannot run successfully.
- Test Android 16 / API 36 target SDK compliance and Google Play requirements on a real device before public rollout.
